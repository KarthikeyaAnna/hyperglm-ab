# HyperGLM-R · [A] vs [B]: does explicit reasoning help a scene-graph LLM?

One controlled experiment. The same model, the same data, the same items, the same metrics. The only difference:

* **[A] answer only** — the model outputs the answer.
* **[B] reasoning + answer** — the model first writes one evidence line per relationship, then the answer.

Anything [B] wins by is attributable to the reasoning chain, not to the format, the data or the decoding.

## Dataset: Action Genome

* Videos of everyday activity, annotated per frame with the person's relationships to each object:
  36 object classes, 25 relationship types in three groups — **attention** (looking_at, not_looking_at, unsure),
  **spatial** (in_front_of, behind, on_the_side_of, above, beneath, in), **contacting** (holding, touching,
  carrying, wearing, eating, not_contacting, …). The subject is always the person, so one *slot* = (object, group).
* **Split by video, no overlap:** train 6,951 / val 826 / test 1,810 videos. Test is Action Genome's official test
  set; val is carved out of train by a hash of the video id. All statistics (transition tables, priors) are built
  from **train minus val** only.
* **Two tasks**
  * **SGA** (scene graph anticipation): observe the first 90 % of a video's annotated frames, predict every
    relationship in all remaining frames. 1,785 test items.
  * **RR-hard** (hidden relationship): one slot is hidden in *every* frame shown; infer it from the rest of the
    graph. 1,810 test items.

## Method

1. **The scene graph becomes text.** Per slot, a run-length timeline over the observed frames
   (`holding@10-147 | touching@166 | holding@201-269 (now, 5 frames)`), plus HyperGLM's procedural graph
   (transition statistics) for the current states.
2. **The answer lists only changes:** `{"changes": [["cup","contacting",["holding"],690]]}`. Any slot not listed
   keeps its state; a change holds from its frame until that slot's next change. This is lossless with respect to
   the full future graph (asserted for every item at build time) and keeps answers short, so they never get cut off.
3. **[B]'s reasoning chain** is generated by code from the gold labels plus the input statistics — no distillation
   from a bigger LLM, so nothing enters the chain that the model could not have derived from its own input.
4. **Decoding for the metrics:** 4 samples per item at temperature 1.0 → a vote fraction per candidate relationship.
   A change is predicted when its vote ≥ τ, with **τ chosen on val and reused unchanged on test**. The same votes
   give a confidence-ranked list for R@K.

### LoRA / training setup

| | |
|---|---|
| Base model | Qwen3-8B (bf16), thinking mode off |
| Adapter | LoRA r = 64, α = 128, dropout 0.05, on **all linear layers** (~175 M trainable of 8 B) |
| Objective | SFT, loss on the completion only (prompt masked) |
| Data | 5,000 SGA + 3,000 RR-hard, the same seeded subset for [A] and [B] |
| Schedule | 1 epoch, lr 2e-4 cosine, warmup 3 %, effective batch 16 (micro-batch 8 × 2), max length 4,096 |
| Efficiency | length-grouped batches (~5× faster than random batching), gradient checkpointing, adapter merged for decoding |
| Hardware | one Kaggle RTX PRO 6000 (96 GB) per run |

## What our annotations look like

Full, real examples are in `examples/` — read these to see exactly what the model is trained on:

| file | content |
|---|---|
| `examples/sga.txt` | SGA prompt, target [A] and target [B] |
| `examples/rr_hard.txt` | RR-hard prompt and both targets |

Target **[A]** is the answer alone:

```json
{"changes":[["phone/camera","attention",["looking_at"],690],["phone/camera","spatial",["above","in_front_of"],690]]}
```

Target **[B]** is one line per slot, then the same answer:

```
<infer>
clothes/attention: not_looking_at (stay 0.79 at 5 frames held; survives the horizon 0.77; else looking_at 0.61; slot changed 2x) -> stays
clothes/spatial: in (stay 0.94 at 9 frames held; survives the horizon 0.70; else in_front_of 0.33) -> stays
phone/camera/attention: not_looking_at (stay 0.67 at 1 frames held; else looking_at 0.65; slot changed 8x) -> looking_at from 690
</infer>
<answer>{"changes":[["phone/camera","attention",["looking_at"],690], ...]}</answer>
```

Every number in an `<infer>` line comes from the prompt or from train-set statistics; only the decision after `->`
comes from the gold future.

## [A] vs [B] results (Action Genome test, scored once with τ from val)

| Metric | [A] answer only | [B] reasoning | [B] − [A] |
|---|---|---|---|
| **Transition F1** (are the *changes* right) | 22.8 | **26.3** | **+3.44 [+1.92, +5.10]** ✅ |
| R@10 | **89.3** | 88.6 | −0.70 [−0.96, −0.45] |
| mR@10 | **65.3** | 62.0 | −3.3 (per-class metric, no item-level pairing) |
| RR-hard accuracy | 65.1 | **65.4** | +0.33 [−0.72, +1.38] (no difference) |
| Parse rate | 97.9 % | **99.9 %** | +2.0 (no CI: a rate, not a per-item score) |
| Changes predicted per video (≈3 are real) | 13.37 | **5.25** | −8.1 (descriptive) |

Paired differences use a bootstrap over the 1,785 (SGA) / 1,810 (RR-hard) test items, 4,000 resamples, seed 0.
Every model number above is reproducible from `results/score_{A,B}_test.json`; the baselines from
`results/baselines_test_full.json` and `results/gbm_reference.json`.

## Layout

```
src/hyperglm_r/    data.py / procedural.py = graph + transition statistics · r13.py = prompt+answer format,
                   parsing, votes, decisions, ranking · metrics.py = R@K, transition F1, baselines
scripts/           build_ag_graphs.py → build_tasks.py → build_tasks_r13.py
                   train_sft.py (SFT+LoRA) · generate_r13.py (greedy or sampled) · score_r13.py
                   gbm_reference_r13.py (the non-LLM reference, CPU)
kaggle/            run_pilot13_{A,B}.py + metadata examples (one RTX PRO 6000 session each)
results/           score_{A,B}_{val,test}.json, baselines_test_full.json, gbm_reference.json
examples/          real prompts and both targets for both tasks
tests/             test_r13.py — format, decoding and voting unit tests (no data needed)
DESIGN.md          the design and pass/fail targets, fixed before the run
RESULTS.md         the full result write-up
```

## Reproduce

```bash
pip install -r requirements.txt
export HYPERGLM_DATA=/path/to/data          # Action Genome annotations in $HYPERGLM_DATA/action_genome/annotations
python scripts/build_ag_graphs.py && python scripts/build_tasks.py
python scripts/build_tasks_r13.py
python tests/test_r13.py

# GPU: train [B] and [A], generate, score (or run kaggle/run_pilot13_{B,A}.py for all of it)
python scripts/train_sft.py --model Qwen/Qwen3-8B --condition B --limits 5000 3000 --select_seed 0 \
  --train $HYPERGLM_DATA/tasks_r13/ag_sga13_train.jsonl $HYPERGLM_DATA/tasks_r13/ag_rr_train.jsonl \
  --max_target_chars 4000 --max_length 4096 --batch 8 --grad_accum 2 --group_by_length --out runs/sft_B
python scripts/generate_r13.py --model Qwen/Qwen3-8B --adapter runs/sft_B --condition B --samples 4 --temperature 1.0 \
  --files $HYPERGLM_DATA/tasks_r13/ag_sga13_test.jsonl --max_new_tokens 1800 --out runs/gen_B_test_vote4_sga.json
python scripts/score_r13.py --split test --gen runs/gen_B_test_vote4_sga.json runs/gen_B_test_greedy_rr.json \
  --tau_from runs/score_B_val.json --out runs/score_B_test.json
```

Baselines and the non-LLM reference run on CPU in minutes; only training and generation need the GPU.
